GPT Plus 휴대폰 구형 노트북 하나로 쌀먹하기

ChatGPT Plus, Remote Desktop Commander, Codex, Git/GitHub, Google Drive를 역할별로 나눠 휴대폰에서 개발·실행·검증까지 이어가는 구조입니다. 제목의 “구형 노트북”은 실제 사용 예시일 뿐이며, 평소 쓰는 데스크톱이나 별도 서버·VM도 같은 방식으로 연결할 수 있습니다.

ChatGPT = 지휘/검증RDC = 빠른 손발Codex = 개발자
제작 고지 — 이 페이지의 본문, 문장 구성, 표, 설명용 도표 및 X 게시물용 이미지는 GPT를 활용해 작성·제작했습니다. 실제 환경 구성, 실행, 테스트와 벤치마크 측정값은 해당 환경에서 직접 확인한 결과를 바탕으로 정리했습니다.

왜 이런 구조를 만들었는가

Codex는 코드 작성과 디버깅에 강하지만 실제 개발 과정에는 코드 작성 외에도 수많은 반복 작업이 있습니다.

단순하지만 자주 하는 작업

파일 읽기, git status, git diff, 로그 확인, 테스트 실행, Python 실행, 프로세스 확인처럼 복잡한 추론이 거의 필요 없는 작업입니다.

추론이 필요한 작업

새 코드 작성, 버그 원인 분석, 여러 파일 리팩터링, 테스트 설계, 복잡한 기능 구현처럼 코드 문맥을 이해하고 판단해야 하는 작업입니다.

모든 작업을 Codex에 맡겨도 수행은 가능하지만, ChatGPT Plus처럼 Codex 사용량이 제한된 환경에서는 단순 작업에까지 에이전트 사용량을 소비하는 것이 아까울 수 있습니다.

생각이 필요한 작업과 그냥 실행하면 되는 작업을 분리합니다. 성능을 포기해서 적게 쓰는 것이 아니라, 비싼 추론을 비싼 추론이 필요한 곳에만 사용합니다.

사용자는 휴대폰에서 자연어로 작업을 요청합니다. ChatGPT가 작업 범위와 검증 조건을 정하고, 단순 파일·터미널 작업은 RDC가 처리합니다. 실제 코드 작성이나 수정이 필요하면 연결된 PC나 서버의 Codex CLI를 호출합니다. 긴 계산은 해당 실행 환경에서 처리하고, 코드는 Git에 기록하며 실행 결과는 Google Drive에 저장합니다.

2. 각 도구의 역할

ChatGPT — PM / 검증자요청 해석, 작업 범위 설정, RDC와 Codex 중 사용할 도구 선택, 결과 검증, 다음 행동 결정을 담당합니다.
RDC — 빠른 손발파일 읽기·쓰기, 터미널 명령, Git 상태 확인, 테스트 실행, 로그와 프로세스 확인을 담당합니다.
Codex — 코드 개발자실제 코드 작성·수정, 버그 원인 분석, 리팩터링, 복잡한 다중 파일 구현을 담당합니다.
연결된 PC/서버 — 실행 환경평소 쓰는 데스크톱, 남는 노트북, 직접 관리하는 서버나 VM에서 Python, 자동 실행기, 데이터 처리와 장시간 분석·테스트를 수행할 수 있습니다.
Git / GitHub — 코드의 역사commit, branch, diff와 변경 이력을 통해 어떤 코드로 실행했는지 추적합니다.
Google Drive — 실행 결과 저장소대형 데이터, 실행 결과, 로그와 상태 파일을 저장합니다.

3. 왜 Codex 하나로 전부 처리하지 않는가

Codex도 파일을 읽고 터미널을 실행하고 테스트할 수 있습니다. 따라서 사용량이나 비용에 여유가 많고 하나의 에이전트로 모든 작업을 처리하는 편이 더 중요하다면 Codex만 사용하는 방식도 충분히 합리적입니다.

차이는 가능 여부가 아니라 자원 배분입니다. Codex는 단순 명령 실행기가 아니라 AI 에이전트이므로 작은 작업에도 요청 해석, 상황 파악, 도구 선택, 실행, 결과 확인 과정이 붙습니다.

4. 실제 속도와 Codex 사용량 비교

같은 단순 작업인 bench_target.txt 읽기 + git status --porcelain을 실제 구형 노트북 환경에서 비교했습니다.

방식실행 시간inputcached / uncachedoutput

Codex Luna / low25.69초42,53337,120 / 5,413224

측정 해석 주의 — 이 수치는 모델 자체의 절대 성능 benchmark가 아니라 특정 시점의 구형 노트북·네트워크·서버 환경에서 동일한 자잘한 작업을 각 실행 경로로 처리한 end-to-end 실측입니다. Astra 추가 1회 시도는 서버 capacity 오류로 실패했으므로 49.11초를 Astra의 일반적인 속도로 단정하지 않습니다.

초기의 더 가벼운 실행 경로에서는 RDC 약 96ms, Codex Luna/low 약 20.64초로 약 200배 수준의 차이가 관찰된 적도 있습니다. 이후 remote persistent 조건에서는 0.663초 대 25.69초로 측정됐습니다. 따라서 “항상 200배 빠릅니다”가 아니라 “단순 deterministic 작업에서는 실행 도구와 AI 에이전트 사이에 매우 큰 latency 차이가 관찰될 수 있습니다”라고 표현하는 것이 정확합니다.

“RDC는 토큰을 안 먹습니다”의 정확한 의미

RDC로 직접 실행한 파일·터미널 작업은 Codex agent usage를 소비하지 않습니다. ChatGPT 대화와 작업 판단 자체에 모델 처리가 전혀 없다는 의미는 아닙니다. 또한 위 표의 raw token 수와 ChatGPT Plus 화면에 표시되는 Codex 할당량 소모율도 동일한 개념은 아닙니다.

5. 실제 사용 흐름

예를 들어 휴대폰에서 “이 분석 작업을 실행하고 오류가 있으면 수정한 뒤 결과를 알려주세요.”라고 요청합니다.

1

요청

휴대폰에서 자연어로 작업을 전달합니다.

2

RDC 확인

파일, 로그, Git 상태, 테스트 조건을 빠르게 확인합니다.

3

Codex

코드 수정이 필요할 때만 작성·디버깅을 맡깁니다.

4

실행·저장

연결된 PC나 서버에서 실행하고 코드는 Git, 결과는 Drive에 기록합니다.

5

최종 판정

ChatGPT가 PASS/FAIL, 핵심 수치와 다음 행동을 정리합니다.

코드 수정이 필요하지 않으면 Codex 단계는 생략됩니다. 수정 후 테스트가 실패하면 필요한 부분만 다시 Codex에 전달하고 RDC가 재검증합니다. 사용자는 중간에 PowerShell을 복붙하거나 여러 앱을 오갈 필요 없이 휴대폰에서 결과와 필요한 의사결정만 확인합니다.

6. Git과 Google Drive를 둘 다 쓰는 이유

Git / GitHub = 코드와 버전

코드, commit, branch, diff, 테스트와 변경 이력을 관리합니다. 어떤 코드 버전으로 결과가 만들어졌는지 추적하는 provenance 역할을 맡습니다.

Google Drive = 실행 결과와 데이터

대형 데이터, 실행 결과, 로그와 상태 파일처럼 용량이 크거나 자주 갱신되는 실행 artifact를 관리합니다.

Git으로 전환한다고 Google Drive를 완전히 없애는 구조가 아닙니다. 두 저장소가 서로 경쟁하는 것이 아니라 각자 잘하는 영역을 맡습니다.

7. Remote Desktop Commander를 ChatGPT에 추가하는 방법

이 구조를 따라 하려면 먼저 제어할 컴퓨터에서 RDC의 remote device agent를 실행하고, 그다음 ChatGPT에 Remote Desktop Commander를 연결하면 됩니다.

1) 제어할 컴퓨터 준비

Windows, macOS, Linux에서 사용할 수 있으며 Node.js 18 이상이 필요합니다. 노트북일 필요는 없습니다. 평소 쓰는 데스크톱, 남는 PC, 직접 관리하는 외부 서버나 VM도 같은 방식으로 사용할 수 있습니다.

npx @wonderwhy-er/desktop-commander@latest remote

명령을 실행하면 인증용 코드가 표시됩니다. 브라우저에서 로그인한 뒤 코드가 일치하는지 확인하고 기기를 승인합니다. 터미널에 Device ready가 표시되면 연결 준비가 끝납니다.

2) ChatGPT에 RDC 연결

가장 간단한 방법은 ChatGPT의 Remote Desktop Commander 앱을 추가하고 안내에 따라 같은 계정으로 연결하는 것입니다.

Remote MCP를 직접 연결하는 경우 ChatGPT의 Apps & Connectors에서 Developer mode를 켠 뒤 다음 endpoint를 connector로 추가합니다.

https://mcp.desktopcommander.app/mcp

3) 연결 확인

처음에는 “연결된 컴퓨터의 홈 디렉터리를 보여주세요.”, “Node.js 버전을 확인해주세요.”처럼 읽기 전용 요청으로 테스트하는 것이 좋습니다. 여러 컴퓨터를 같은 계정에 연결해 작업마다 사용할 기기를 구분할 수도 있습니다.

중요 — RDC는 연결된 컴퓨터에서 현재 사용자 계정 권한으로 파일과 터미널을 다룹니다. 신뢰하는 기기만 연결하고 MFA를 사용하는 것이 좋습니다. 기기는 agent가 실행 중일 때만 원격으로 접근할 수 있으며, Ctrl+C로 agent를 종료하면 접근도 중단됩니다. 외부 서버나 VM에 연결할 때는 특히 권한과 저장된 인증정보 범위를 최소화하는 편이 안전합니다.

공식 안내: ChatGPT + Desktop Commander · Remote Desktop Commander 공식 문서

8. 이 구조가 특히 잘 맞는 경우

  • ChatGPT Plus 범위에서 Codex 사용량을 효율적으로 배분하고 싶은 경우
  • 휴대폰만으로 원격 개발·연구 작업을 자주 지시하는 경우
  • 파일 확인·로그 확인·테스트 같은 반복 작업이 많은 경우
  • 데이터 처리나 장시간 분석처럼 로컬 실행이 필요한 경우
  • 코드와 결과를 Git과 Drive로 분리해 추적하고 싶은 경우

반대로 굳이 필요하지 않은 경우

Codex 사용량에 여유가 충분하고 하나의 에이전트에서 모든 터미널·코딩 작업을 처리하는 단순함이 더 중요하다면 Codex 단독 방식이 더 편할 수 있습니다. 이 구조의 목표는 절대적인 AI 성능 향상보다 사용량·속도·역할 분담의 효율입니다.

9. 한 줄로 정리하면

단순 PC 작업 → RDC · 코드 작성/디버깅 → Codex · 긴 계산 → 연결된 PC/서버 · 코드 기록 → Git · 실행 결과 → Drive · 전체 판단 → ChatGPT입니다.

농담 섞어 표현하면 “쌀PT”입니다. 비싼 AI를 무조건 덜 쓰는 것이 목적이 아니라, 비싼 추론을 비싼 추론이 필요한 작업에만 사용하는 구조입니다.

콘텐츠 제작: 본문·표·설명 도표·X 게시물용 이미지는 GPT를 활용해 작성·제작했습니다.

실측: 환경 구성, 실제 명령 실행, 테스트와 벤치마크 수치는 해당 개발 환경에서 확인한 결과를 바탕으로 정리했습니다.
